# Security and disclosure boundary

The public Free Demo Audit intake is intentionally limited to public repository information.

## Do not submit publicly
Do not put any of the following in a GitHub issue:
- passwords, API keys, tokens or credentials;
- private source code or private repository links;
- customer-confidential or regulated data;
- production secrets or internal infrastructure details;
- sensitive vulnerability details that could enable exploitation.

If a potential finding is sensitive, do not publish exploit details in a public request. A private reporting/engagement route must be agreed separately before such material is exchanged.

## Audit boundary
A repository audit is not a penetration test, certification, compliance attestation, legal opinion, or guarantee of security or defect-free software. Findings are bounded to the exact revision, scope, tests and evidence actually reviewed.

## Access principle
The free demo requires no write access and no private repository access. Any future private access must be explicitly authorized and minimized to the agreed scope.
